# Portfolio 5: Distributed and Cloud Databases

## Case Study
Greenfield University Student Results Management System.

## Objective
To explore how distributed and cloud database technologies can improve the availability, scalability and reliability of the university's student results management system.

## Distributed Database Concepts

### 1. Replication
Replication involves maintaining copies of database records across multiple servers to improve availability and support recovery.

### 2. Sharding
Sharding involves splitting a large database into smaller portions and distributing them across multiple servers to improve scalability.

### 3. Availability
The system should remain accessible to students, lecturers and administrators when needed.

### 4. Consistency
The system should ensure that users access accurate and reliable student results.

### 5. Cloud Databases
Cloud databases provide flexible infrastructure, remote access, backup facilities and scalable storage.

## Proposed Architecture
The proposed architecture includes:
- Application layer
- Primary database server
- Secondary replica servers
- Backup storage
- Monitoring services

## Benefits
- Improved database availability.
- Better scalability as student records increase.
- Support for backup and disaster recovery.
- Flexible access to database resources.

## Limitations
Distributed databases require careful management of replication, security, network failures, consistency and operating costs.

## Implementation Status
This portfolio presents a conceptual distributed and cloud database architecture. A live cloud deployment, replication test and sharding implementation have not yet been performed.

## Conclusion
Distributed and cloud database technologies can help Greenfield University build a more scalable, reliable and accessible student results management system.
